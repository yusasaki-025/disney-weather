## 1. 色 (color)

### 1.1 `:root` トークンの 2 重定義 ・ 値食い違い 【重要度 : 高】
- **現状** : `src/styles.css` に `:root` が 3 ブロック (L5 旧 §6.3 配色 / L1233 §0.6.10 TDR トーン / L1707 `--fs-*`)。L5 と L1233 が同じトークン名で**別の値**を定義し、後勝ち (L1233) で L5 は完全に死蔵。
  - 例 : `--accent` L5 `#2f6fb0` / L1233 `#1f4fa3`、`--score-bad` L5 `#d24a4a` / L1233 `#e0544e`、`--bg` `#f4f6f9` / `#f4f7fb`、`--text` `#1d2733` / `#1a2740` など 10+ 個。
- **修正案** : L5 の色トークン群を削除し L1233 に一本化 (`--fs-*` の L1707 は別系統なので残す)。削除前に L5 固有で L1233 に無いキー (`--accent-dark` 等) が無いか差分確認。
- **重要度** : 高 (視覚バグは無いが、今後「どっちが効くか」で確実に事故る)

### 1.2 スコア色が二系統 (SYMBOLS vs `--score-*`) 【重要度 : 高】
- **現状** : スコアバッジ色は `scoring.js` の `SYMBOLS` インライン (`#2E7D32 / #66BB6A / #CDDC39 / #FFA726 / #E53935`、§0.52 の 5 段階信号機)。一方 CSS `--score-excellent/good/fair/bad` は**旧 4 段階の値** (`#2e9e4f / #8fc861 / #f0a93c / #e0544e`) のまま残り、`var(--score-bad)` が「(要確認)」テキスト ・ extreme 警告など **12 箇所**で使用中。
  - 結果 : NG バッジの赤 `#E53935` と「(要確認)」テキストの赤 `#e0544e` が**微妙に違う**。FAIR 橙 `#FFA726` と警告系トークンの橙も別。
- **修正案** : `--score-*` を 5 段階 (best/good/ok/fair/ng) の SYMBOLS と同値に再定義し、`SYMBOLS` も CSS 変数を参照する形にして**単一ソース化**。最低でも `--score-bad` を `#E53935`、警告橙を `#FFA726` に合わせる。
- **重要度** : 高 (同じ「赤/橙」が画面内で 2 トーン)

### 1.3 OK バッジ ライムの彩度突出 【重要度 : 中】
- **現状** : 5 段階 BEST(濃緑)→GOOD(緑)→OK(ライム #CDDC39)→FAIR(橙)→NG(赤) のうち、OK のライムだけ彩度が高く視覚的に浮く (PC/スマホとも)。信号機グラデの中で 1 つだけ蛍光色。
- **修正案** : OK を少しくすませる (例 `#C0CA33` 寄り) か、明度を上げて他と馴染ませる。文字色 `#33691E` は維持。
- **重要度** : 中 (Yuka さん確定の案 A 配色なので、変更可否は要判断)

### 1.4 警告バッジ橙 vs FAIR バッジ橙の不一致 【重要度 : 低】
- **現状** : セル内「風バ可能性あり」バッジ (薄橙 `--warn-bg #fef4e2` + 文字 `#9a6a00`) と、スコア FAIR バッジ (橙 `#FFA726`) は別系統の橙。
- **修正案** : 警告系の橙基準を 1 つ決めて寄せる (役割が違うので必須ではない)。
- **重要度** : 低

### 1.5 雷アイコンの紫が天気アイコン群から浮く 【重要度 : 低】
- **現状** : 6/3 気象庁の「雷」天気アイコンが紫 ・ 他の天気アイコン (雨=青 ・ 曇=灰) と色相が違い目立つ。Open-Meteo 側は灰の雲+小雷で表現が非対称。
- **修正案** : 雷を青系または橙系 (警戒色) に寄せ、ソース間で雷表現を揃える。
- **重要度** : 低

## 2. フォント (font)

### 2.1 font-size トークン未使用 ・ ハードコード散在 【重要度 : 中】
- **現状** : `--fs-xs:11 / --fs-sm:13 / --fs-md:14 / --fs-lg:16 / --fs-xl:18` が定義済みなのに、CSS の font-size は**ほぼハードコード px** (11px×28 / 13px×25 / 12px×19 ...)。さらにトークン外の値が多数 (9,10,12,15,17,20,22,24,26,28,30,32,40,48px) ・ **14.5px** という半端値 (§0.46.11) も。
- **修正案** : 主要テキストを `--fs-*` 参照に置換し、外れ値 (14.5px,9px 等) を最寄りトークンに丸める。見出し用に `--fs-2xl` 等を追加してサイズ段階を定義。
- **重要度** : 中 (現状の見た目は許容だが、今後の調整が揺れやすい)

### 2.2 サブカラー (text-sub/mute) の使い分けが曖昧 【重要度 : 低】
- **現状** : `--text-sub` `--text-mute` が併存。補足テキスト ・ 単位 ・ 鮮度などで使い分け基準が不明瞭。
- **修正案** : 「補足 = sub / 無効 ・ 最弱 = mute」の運用ルールを決め用語集化。
- **重要度** : 低

## 3. 余白 (spacing)

### 3.1 gap 値の散在 【重要度 : 中】
- **現状** : gap が 12 種 (2,3,4,6,8,10,12,14,16,18,20,24px)。最頻は 6/8/4px だが 3px ・ 14px ・ 18px など中途半端な値が混在。
- **修正案** : 4 の倍数 (4/8/12/16/24) を基準にスペーシングスケールを決め、3px ・ 14px ・ 18px を最寄りに統一。
- **重要度** : 中

### 3.2 padding の組み合わせ散在 【重要度 : 低】
- **現状** : `6px 8px` / `10px 8px` / `6px 12px` / `4px 10px` / `8px 10px` 等、似た値が多数。
- **修正案** : セル ・ ピル ・ ボタンで padding 規格を 2-3 種に集約。
- **重要度** : 低
